# Справочник: роли, права, команды, статусы

> **Файл создан автоматически** командой `python tools/gen_manual_ref.py` из контрактов
> `command-catalog-slice1-v8`, `permissions-slice1-v8`, `workflows-slice1-v3`. Не правьте его вручную —
> правьте контракты в `/contracts` и запустите генератор (тест проверяет актуальность).

Права ниже — **действующие временные предположения** (журнал решений, A-03…A-24), которые владелец
продукта может изменить. Интерфейс использует их только как подсказку (скрыть явно недоступное);
решение всегда принимает сервер в момент действия.

## 1. Роли доступа

Роль доступа ≠ должность ≠ подразделение. Глобальные роли выдаёт администратор (раздел «Администрирование»);
роли в проекте — назначения в карточке проекта. Администратор **не получает** бизнес-прав автоматически.

| Код | Роль | Тип |
|---|---|---|
| `admin` | Администратор | глобальная |
| `gip` | ГИП | глобальная |
| `rp` | РП | глобальная |
| `dept_head` | Руководитель отдела | глобальная |
| `lead_engineer` | Ведущий инженер | глобальная |
| `engineer` | Инженер | глобальная |
| `designer` | Конструктор | глобальная |
| `technologist` | Технолог | глобальная |
| `production` | Производство | глобальная |
| `warehouse` | Склад | глобальная |
| `procurement` | Закупка | глобальная |
| `accountant` | Бухгалтерия | глобальная |
| `gip` | ГИП проекта | в проекте |
| `rp` | РП проекта | в проекте |
| `participant` | Участник проекта | в проекте |

Общие правила:

* Правила — ВРЕМЕННЫЕ предположения (Decision Log A-03..A-09) для работающего среза. Владелец продукта должен подтвердить или изменить.
* Роль из клиентского запроса игнорируется: сервер загружает действующие выдачи ролей и назначения в той же транзакции, где производится эффект.
* Роль доступа ≠ должность ≠ подразделение. Admin НЕ получает бизнес-прав автоматически (принцип минимальных привилегий).
* Каждая выдача роли/назначение — отдельная запись с id (= generation). Отзыв и повторная выдача создают новый id; старые согласования не оживают.
* Условие {"authenticated": true} — любой вошедший пользователь, только над собственной учётной записью (проверяется в обработчике).

## 3. Команды и работа без связи

* **полностью офлайн** (`offline_full`) — Полностью доступно офлайн (чтение локального кэша, локальные черновики без эффекта для других).
* **можно без связи (очередь)** (`queued`) — Создаёт локальное изменение в очереди синхронизации. До ответа сервера это НЕ подтверждённое действие; сервер заново проверяет права, состояние и версию.
* **только при связи** (`online_required`) — Требует актуальной проверки сервера в момент эффекта. Офлайн — отказ с объяснением; ничего не ставится в очередь.

## 4. Статусы и переходы

* Переходы и условия — временные предположения A-02/A-05 (Decision Log). Статус меняется только явной командой.

### Тендер

Начальный статус: **Черновик**. Конечные: **Выигран**, **Проигран**, **Отменён**.

| Из статуса | Можно перевести в |
|---|---|
| Черновик | В работе, Отменён |
| В работе | Заявка подана (зарегистрировано), Отменён |
| Заявка подана (зарегистрировано) | Выигран, Проигран, Отменён |

Причина обязательна для: Проигран, Отменён.

### ТКП

Начальный статус: **Черновик**.

| Из статуса | Можно перевести в |
|---|---|
| Черновик | Согласовано внутри компании |
| Согласовано внутри компании | Черновик, Отправка зарегистрирована (не доказательство получения) |

### Проект

Начальный статус: **Разработка РКД**.

Проект создаётся явным действием «Начать РКД» только из тендера в статусе: **Выигран**. Один проект на тендер.

### Задача

Начальный статус: **Открыта**. Конечные: **Отменена**.

| Из статуса | Можно перевести в |
|---|---|
| Открыта | В работе, Отменена |
| В работе | Выполнена, Открыта, Отменена |
| Выполнена | Открыта |

Исполнитель может сам переводить свою задачу: Открыта → В работе; В работе → Выполнена, Открыта.

Причина обязательна для: Отменена, возврат в работу.

Основание: A-13.

### Документ

Обозначение документа уникально в пределах проекта.
Версия документа неизменяема: файл, размер и SHA-256 фиксируются при добавлении; новая правка — новая версия с номером n+1.

Основание: A-15.

### Складской резерв

Начальный статус: **Действует**. Конечные: **Израсходован**, **Снят**.

| Из статуса | Можно перевести в |
|---|---|
| Действует | Израсходован, Снят |

Основание: A-23.
