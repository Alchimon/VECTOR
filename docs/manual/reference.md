> правьте контракты в `/contracts` и запустите генератор (тест проверяет актуальность).

Права ниже — **действующие временные предположения** (журнал решений, A-03…A-24), которые владелец
продукта может изменить. Интерфейс использует их только как подсказку (скрыть явно недоступное);
решение всегда принимает сервер в момент действия.

## 1. Роли доступа

Роль доступа ≠ должность ≠ подразделение. Глобальные роли выдаёт администратор (раздел «Администрирование»);
роли в проекте — назначения в карточке проекта. Администратор **не получает** бизнес-прав автоматически.

| Код | Роль | Тип |
|---|---|---|
| `admin` | Администратор | глобальная |
| `gip` | ГИП (главный инженер проекта) | глобальная |
| `rp` | РП (руководитель проекта) | глобальная |
| `dept_head` | Руководитель отдела | глобальная |
| `lead_engineer` | Ведущий инженер | глобальная |
| `engineer` | Инженер | глобальная |

| `technologist` | Технолог | глобальная |
| `production` | Производство | глобальная |
| `warehouse` | Склад | глобальная |

| `gip` | ГИП проекта (главный инженер проекта) | в проекте |
| `rp` | РП проекта (руководитель проекта) | в проекте |
| `participant` | Участник проекта | в проекте |

Общие правила:

* Правила — ВРЕМЕННЫЕ предположения (Decision Log A-03..A-09) для работающего среза. Владелец продукта должен подтвердить или изменить.
* Роль из клиентского запроса игнорируется: сервер загружает действующие выдачи ролей и назначения в той же транзакции, где производится эффект.
* Роль доступа ≠ должность ≠ подразделение. Admin НЕ получает бизнес-прав автоматически (принцип минимальных привилегий).
* Каждая выдача роли/назначение — отдельная запись с id (= generation). Отзыв и повторная выдача создают новый id; старые согласования не оживают.
* Условие {"authenticated": true} — любой вошедший пользователь, только над собственной учётной записью (проверяется в обработчике).
* Замещение (D-34): глобальная роль, переданная на срок, действует у замещающего, пока действует замещение и пока у носителя есть своя роль; без цепочек; роль «Администратор» не передаётся.
* Замещение в проекте (D-35): роль в проекте (ГИП, РП, участник), переданная на срок, действует у замещающего только в этом проекте и только пока у носителя есть назначение с этой ролью; глобальной роли не даёт.
* Производство (D-36): роль мастера отдельно не заводится (OQ-15 → A-42) — наряды выпускает и закрывает РП проекта (или его замещающий в проекте, D-35), резерв — руководитель отдела; операции исполняет роль «Производство» только по назначению на операцию (проверяется в обработчике).
* Условие с "in_project": true (D-38): глобальная роль из условия учитывается только у участника ЭТОГО проекта (своё назначение в проект или роль в проекте по замещению). Так «ведущий инженер» правит паспорта только своих проектов.
* Качество (D-39): рекламации и CAPA ведут РП и ГИП проекта (резерв — руководитель отдела); ECR подаёт любой участник проекта; решение по ECR и утверждение ECO — ГИП проекта (не автор). Проверку эффективности делает НЕ тот, кто составлял план, выполнял действия или отправлял на проверку; ECO проверяет не тот, кто внедрял (проверяется в обработчике).
* ОТК (D-40 / D-41, ответы владельца на A-46 и A-47): роль «Технический контроль» (otk — отдел технического контроля) — глобальная, но действует ПО ПРОЕКТАМ: только в проектах, куда сотрудник ОТК назначен участником (условие in_project; назначает ГИП или РП). Там он видит изделия, наряды, техпроцессы и качество (без денег), регистрирует и ведёт рекламации наравне с РП и ГИП, проверяет эффективность CAPA и внедрение извещений (правило «другой человек» действует и для ОТК), подаёт запросы на изменение. Решения по ECR и утверждение ECO остаются за ГИП проекта.
* Рабочее время (D-42): дневной отчёт ведёт сам сотрудник — любой вошедший, только свой (проверяется в обработчике); принимает или возвращает руководитель отдела (dept_head, в т. ч. замещающий), но не свой отчёт. Сотрудников вне оргструктуры руководитель отдела видит всех (A-48); в оргструктуре — только своих подразделений (D-44).
* Оргструктура (D-44, ответ владельца на A-48 п. 1): филиалы, структуры и отделы, связи «входит в», руководители и сотрудники. Ведёт администратор (org.manage — временное правило, вопрос A-50); видят все вошедшие. Подразделение и должность прав не дают. Дневной отчёт сотрудника в оргструктуре уходит руководителю его подразделения (или ближайшего вышестоящего) и его замещающему; принять или вернуть может руководитель подразделения по цепочке вверх с ролью «Руководитель отдела» (или его замещающий) — проверяется в обработчике. Сотрудники вне оргструктуры — по правилу D-42.
* Сквозные потоки проекта (D-56, ответы владельца 2026-11-16): статус проекта, потоки и риск-разрешения в рамках проекта ведёт РП (резерв — руководитель отдела). Лиды (sales_opportunities) — тендерный отдел и менеджеры: глобальные роли gip, rp, dept_head (A-57).
