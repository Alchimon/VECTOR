# 54. Соответствие требованиям ФСТЭК, КИИ и реестру отечественного ПО (D-84)

> Статус: направление принято владельцем (2026-11-25): **«Наша платформа определённо должна выполнять требования
> ФСТЭК и КИИ»**. Это карта: что уже есть, что добавить, в каком порядке. Формальная сертификация — отдельный
> бюджет и сроки после первых продаж (решение владельца по факту спроса).

## 1. Зачем

Госорганам и госкомпаниям запрещено закупать иностранное ПО (ПП РФ № 1236) — наш основной рынок. Заказчики
со значимыми объектами КИИ (187-ФЗ) обязаны применять сертифицированные средства защиты; если мы хотим туда —
нужны требования ФСТЭК (приказы № 17 и № 21). Включение в **реестр отечественного ПО** даёт: право на закупки
госсектором, льготу по НДС (пп. 26 п. 2 ст. 149 НК РФ), гранты.

## 2. Что уже есть в платформе (закрывает часть требований «бесплатно»)

| Требование | Где в платформе |
|---|---|
| Идентификация и аутентификация (упр. 1.1–1.5 приказа 17) | Учётные записи, пароли Argon2id, политика паролей, блокировка после неудач, сеансы с простаиванием/абсолютным сроком, отзыв сеансов |
| Управление доступом (упр. 2.x) | Роли и полномочия с основанием и сроком, матрица прав версионируется (contracts), замещения с журналом |
| Регистрация событий безопасности (сб. и хр.) | Неизменяемый журнал аудита (только добавление), без секретов; история каждого объекта |
| Целостность | Хэши SHA-256 файлов и утверждённых содержимых (ТП, заказы), версии объектов, триггеры неизменяемости |
| Криптография канала | TLS с сертификатом CA компании; секреты не в конфиге/журналах; ключи с правами 600 |
| Резервное копирование | `vector-server backup/restore`, проверенные копии, учебное восстановление (restore-drill) |
| Документация | Администратор, пользователь, архитектура, установка, обновление, регламенты |

## 3. Что добавить (план)

### 3.1. ГОСТ-криптография — главный пробел для КИИ

Сейчас: Ed25519/AES/TLS (западные алгоритмы). Для КИИ и госсектора требуется **ГОСТ Р 34.10-2012 /
34.12-2015 (Кузнечик/Магма)** на канале и в подписях.

Решение (архитектура уже готова к этому):

* **Криптопровайдер как сменный модуль** — ✅ сделано в контуре лицензий (D-86): `alg` в файле лицензии,
  `register_verifier` в `core/modules.py`; профиль ГОСТ Р 34.10-2012 проверяет сертифицированный СКЗИ заказчика
  (КриптоПро CSP / ViPNet) через адаптер внедрения — свою реализацию ГОСТ без сертификата не пишем, юридического
  веса она не имеет. Старые лицензии (ed25519) продолжают проверяться. Осталось: тот же приём для подписей
  актов/документов (сейчас SHA-256 содержимого) — при внедрении на площадке с КИИ.
* TLS по ГОСТ — на уровне веб-сервера/прокси перед нашим сервером (шлюз с ГОСТ-TLS — распространённая схема
  у КИИ-заказчиков), прикладной код не трогаем. Вариант «свой TLS-стек на ГОСТ» — отклонён: не проходим
  сертификацию сами.

### 3.2. Требования приказов 17/21, которых не хватает

| Пробел | Что делаем | Когда |
|---|---|---|
| Антивирусный контроль, контроль целостности среды | Интеграция с СЗИ заказчика; ✅ целостность файлов поставки по манифесту SHA-256 в `vector-server check` (D-85) | сделано (D-85); СЗИ-интеграция — регламент |
| Управление конфигурацией/изменениями | Уже: версии схемы, миграции с копией, аудит; ✅ отчёт «изменения конфигурации за период» из журнала — `vector-server audit-config-changes --since` (D-87) | сделано |
| Защита от несанкционированного доступа к носителям | Шифрование БД на диске — средствами СУБД (TDE в MS SQL / pgcrypto-совместимые схемы) или шифрованный раздел ОС; документировать регламент | документация + проверка в check |
| Очистка памяти/магнитных носителей | Регламент для администратора (docs/ops), само ПО данных за пределы контура не выносит | документация |

### 3.3. Реестр отечественного ПО — условия и наша готовность

| Условие | Статус |
|---|---|
| РФ-правообладатель, исключительные права | ✅ код наш, служебные произведения (ст. 1295 ГК РФ); договоры с разработчиками — владельцу (docs/legal) |
| Не из-под иностранного контроля; иностранная выручка < 30 % | ✅ (контроль у владельца) |
| Выплаты РФ ≥ 50 % выручки по ПО | обеспечивается ведением (продаём в РФ) |
| Сайт на русском, документация | ✅ |
| Исходники/депонирование по запросу | ✅ репозиторий; регистрация в Роспатенте (необязательно, рекомендуется) |
| Классы ПО: СУБД/офисные/САПР/PDM | наши модули попадают в классы реестра; экосистема расширяет классы |

Заявка подаётся при первом коммерческом релизе (1.0.0); подготовка пакета — docs/legal + этот документ.

### 3.4. Товарный знак и депонирование

* Заявка в Роспатент на «ВЕКТОР / VECTOR» (МКТУ 9, 42) — до первых продаж; действие владельца (OQ-53в).
* Депонирование программы для ЭВМ (Роспатент, необязательно) — рекомендуется для споров об авторстве: дёшево,
  делается за неделю.

## 4. Что НЕ делаем

* Свою криптореализацию ГОСТ без сертификата (юридического веса нет, риск ошибки высокий).
* Сертификацию ФСТЭК «впрок» — только под подтверждённый спрос (дорого, долго, требует заморозки версии).
* Ослабление текущих мер ради «галочки»: карта выше показывает, что базовая гигиена уже на уровне требований.
