# 01. Карта предметной области, роли, пользовательские задачи, термины

## 1. Карта предметной области (bounded contexts)

                         └────────────────────────────────────────────────────────────────────────────────┘
 КОММЕРЦИЯ                       ПРОЕКТИРОВАНИЕ                       ПРОИЗВОДСТВЕННЫЙ КОНТУР
 ┌───────────────┐   явное      ┌────────────────────┐  фиксация     ┌───────────────┐   ┌──────────────┐
 │ Заказчики     │  «Начать     │ Проекты, комплекты │  версий       │ Закупки       │──▶│ Склад        │
 │ CRM/сделки    │   РКД»       │ Задачи             │──────────────▶│ (потребность, │   │ (остатки,    │
 │ Тендеры, ТКП  │─────────────▶│ Документы, версии  │               │  заказ, факт) │   │  резервы,    │

                                └────────────────────┘                                     │

согласование или юридическое доказательство следующего этапа.

## 2. Роли доступа, должности, подразделения

Три независимых понятия (R-21, R-39):

| Понятие | Что это | Пример | Даёт права? |
|---|---|---|---|
| **Должность** | Кадровый атрибут | «Ведущий инженер-конструктор» | **Нет** |
| **Подразделение** | Узел оргструктуры, руководитель | «Отдел АСУ ТП» | Только как *контекст* правила (например, «руководитель отдела для своих сотрудников») |
| **Роль доступа** | Выдача с id (generation), сроком, основанием | `designer`, срок до 2027-01-31 | Да, через матрицу правил |
| **Назначение в проекте** | Роль в конкретном проекте | ГИП проекта P-001 | Да, только в пределах проекта |
| **Замещение** | Временная выдача роли/назначения с явным сроком и основанием | «И.о. руководителя отдела на время отпуска» | Да, пока срок действует; история сохраняется |

Роли доступа (минимальный набор из задания; новые не вводятся без необходимости, гостевого входа нет):

| Код | Роль | Основной фокус |
|---|---|---|
| `admin` | Администратор | Пользователи, роли, настройки, диагностика, назначение ГИП. **Не получает бизнес-прав автоматически** (D-09) |
| `gip` | ГИП | Техническое руководство проектами, согласования |
| `rp` | РП | Управление проектом: сроки, участники, перенос файлов (одобрение) |
| `dept_head` | Руководитель отдела | Загрузка отдела, согласования в зоне отдела, приёмка дневных отчётов |
| `lead_engineer` | Ведущий инженер | Ведение комплекта/раздела, проверка документов |
| `engineer` | Инженер | Документы, расчёты, задачи |
| `designer` | Конструктор | Конструкторская документация, 3D |
| `technologist` | Технолог | ТП, нормы, CAPP |
| `production` | Производственный исполнитель | Операции наряда, факт, таймер |
| `warehouse` | Склад | Приход, выдача, перемещение, инвентаризация, подтверждения |
| `procurement` | Закупка | Заказы, поставщики, подтверждения пополнения |
| `accountant` | Бухгалтерия | Чтение разрешённых финансовых данных и настроек, сверка |

Открытый вопрос **OQ-02**: кто ведёт заказчиков/тендеры, если в компании есть коммерческий отдел без
перечисленных ролей. Сейчас (A-03) — `gip`, `rp`, `dept_head`; отдельная роль не вводится.

## 3. Пользовательские задачи по ролям (главное — «что у меня в работе»)

| Роль | Ежедневные задачи | Редкие, но критичные |
|---|---|---|
| РП | Тендеры и ТКП в работе, сроки, задачи команды, начало РКД, состав комплектов | Одобрение переноса файлов, назначение участников |
| ГИП | Согласования, проверка комплектов, фиксация расчётов, замечания | Назначение РП, решения по ECO |
| Руководитель отдела | Загрузка отдела, приёмка дневных отчётов, согласование ТКП | Перераспределение задач, замещение |
| Инженер/конструктор | Мои задачи, документы и версии, замечания, расчёт комплекта (черновик) | Загрузка без передачи, подготовка рабочего архива |
| Технолог | ТП, операции, нормы, карты-черновики | Утверждение ТП, ответ по нормам |
| Производство | Мои операции наряда, таймер, факт, проблемы | Работа без сети |
| Склад | Приходы, выдачи, резервы, подтверждения пополнения/перемещения | Инвентаризация, корректировки |
| Закупка | Потребности, заказы, факты поставки, подтверждения пополнения | Аналоги (явное решение) |
| Бухгалтерия | Сверка фактов, чтение разрешённых настроек и отчётов | — |
| Администратор | Учётные записи, роли, конфигурация, диагностика, резервные копии | Назначение ГИП, восстановление |

## 4. Термины (русский — основной язык интерфейса)

| Термин в ВЕКТОР | Пояснение | Не путать с |
|---|---|---|
| ВЕКТОР / VECTOR | Название платформы (рус./англ.) | ENGИ, EPC — не названия платформы |
| Тендер | Конкурентная процедура заказчика; ведётся до проекта | Проект |
| ТКП | Технико-коммерческое предложение по тендеру; черновик → согласовано → «отправка зарегистрирована» | КП (коммерческое предложение — отдельная сущность, R-05) |
| Начать разработку РКД | Явное действие, создающее инженерный проект по тендеру | Победа в тендере (сама проект не создаёт) |
| Комплект | Часть проекта (система/марка), имеет свои документы и расчёты | Документ |
| Версия документа | Внутренняя монотонная последовательность (1,2,3…) | **Метка** (А, 01, А1 — вводится человеком, отдельно) |
| Расчёт комплекта (спецификация) | Перечень позиций комплекта; «BOM» в контексте проектирования | «Закупочная потребность» (BOM в контексте закупки) |
| Зафиксировать комплект | Создать неизменяемую версию расчёта, которая может войти в общий итог | «Сохранить расчёт» (черновик) |
| Общий проектный расчёт | Сумма **зафиксированных** версий комплектов; у каждой фиксации — новая ревизия | Черновые изменения |
| Производственное задание (наряд) | Задание на изготовление qty 1…N по снимку утверждённой ревизии | Задача |
| ТП, CAPP | Технологический процесс; CAPP — автоматизированное планирование ТП | — |
| ЕСТД | Единая система технологической документации (ГОСТ 3.xxxx) | Применимость конкретного стандарта не подтверждена (Q7) |
| ECR / ECO | Запрос на изменение / извещение (приказ) об изменении | Замечание |
| CAPA | Корректирующие и предупреждающие действия | Закрытие рекламации (не доказывает устранение причины) |
| Паспорт экземпляра | Цифровая карточка конкретного изделия с точными связями | Черновой экспорт (не сертификат) |
| Регистрация отправки | Запись пользователя «отправлено тогда-то, так-то» | Доставка, получение, принятие |
| Перенос файлов | Физическое копирование с проверкой и обновлением ссылок | Смена системной привязки |
| Предложение перемещения | Предложение использовать позицию другого проекта | Резерв, заказ или движение |
