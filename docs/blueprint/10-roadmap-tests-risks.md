# 10. План MVP и версий, критерии этапов, тестовая стратегия, риски, открытые решения

## 1. Этапы (каждый — ограниченный diff с причиной, критериями, зависимостями и откатом)

| Этап | Содержание | Вход | Выход (все пункты) | Откат |
|---|---|---|---|---|
| **0. Blueprint + эталон среза 1** | Документы 01–15, контракты, эталонное ядро | Пустой репозиторий | Документы на месте; 36/36 Class A; трассировка 1–46 без пропусков; **подтверждение владельцем A-xx/OQ-xx** | Удалить `docs/`, `contracts/`, `spikes/` (продуктовых данных нет) |

| **5. Производство** | ТП, наряд, снимок, офлайн qty 1/N, факт/таймер, складские операции | Этап 4 | Сценарий С5 (1–6) офлайн; снимок неизменен | — |
| **6. Изменения и качество** | ECR/ECO, рекламации/CAPA, паспорт, эксплуатация | Этап 5 | С5 (7–10) | — |
| **7. Интеграции и люди** | 1С (mock→тест), nanoCAD/КОМПАС, STEP, оргструктура, время, общение, аналитика, центр помощи, админ-центр | По готовности контрактов | Class B по каждой интеграции; Class C только с разрешением | Адаптеры выключаемы |
| **8. Выпуск** | Пилот на тестовых данных, backup/restore, security gates, приёмка | Все gates этапов | Подтверждение владельца; план сосуществования с действующими системами | Пилот не заменяет действующие системы |
| **9. Экосистема** | Модули-программы (Таблицы, Текст, Схема, CAD, Презентации) и лицензирование — [53-ecosystem.md](53-ecosystem.md) | Этап 8, решения владельца (OQ-53) | Каждая фаза — отдельное решение; модуль включается лицензией, не отдельной установкой | Истёкшая подписка = «только чтение», данные не отнимаются |

Релизный контур (версии, gates, каналы, совместимость N-2) — [docs/ops/release.md](../ops/release.md).

**MVP** = этапы 2–4 (коммерция → проект → документы → расчёт → закупка/склад) на целевом стеке с офлайн-режимом.
**v1.x** = производство и качество; **v2** = интеграции 1С/CAD/3D в промышленном режиме; защищённый КП — отдельный gate (13).

## 2. Тестовая стратегия

| Класс | Что | Где | Не доказывает |
|---|---|---|---|
| **A** | Unit/интеграционные на synthetic SQLite, временные файлы, offscreen/UIA-автоматизация; права, история, конкурентность, идемпотентность, отмена, восстановление | CI, локально | Живую БД, реальные Windows/DPI/CAD/1С |
| **B** | DDL/миграции на PostgreSQL/MS SQL в контейнере, compatibility, mock 1С/CAD/файлового хранилища/времени/провайдеров | CI с контейнерами | Runtime на сервере компании |
| **C** | Реальные Windows/DPI, установщик, on-prem развёртывание, нагрузка, сетевые ACL, STEP/CAD, nanoCAD, 1С, пользователи, restore | Только по отдельному разрешению и плану | — |

Обязательные проверки (сквозные): пусто vs ноль vs неизвестно; денежные границы и >4 знаков; Excel
>15 значащих цифр; валюта/единица; версия снимка; истечение и повторная выдача роли; повтор/дубль;
гонка; изменённый файл; устаревшее подтверждение; потеря связи; сбой между ФС и БД; неизвестный
исход commit; восстановление из backup. Исторические данные не округляются и не переписываются.

Правила отчётности: для каждого прогона — команда и точный результат; каждый `skip` — с причиной;
выводы о коде — `file:line`; xfail не скрываются.

## 3. Реестр рисков

| ID | Риск | Вероятн. | Влияние | Мера |
|---|---|---|---|---|
| RK-01 | Объём продукта (28 доменов) несоразмерен команде | Высокая | Высокое | Вертикальные срезы, MVP = этапы 2–4, жёсткие критерии выхода |
| RK-02 | Офлайн-синхронизация усложняет каждый модуль | Высокая | Высокое | Единый каталог классов команд; по умолчанию `online_required` для эффектов; эталонные векторы |
| RK-03 | Стек выбран без spikes | Средняя | Высокое | Этап 1 обязателен; S0 переносимые контракты |
| RK-04 | Права неверно отражают реальную организацию | Высокая | Высокое | Предположения A-xx помечены; подтверждение владельцем; матрица генерируется из контракта |
| RK-05 | Интеграция с 1С/CAD без тестовых стендов | Высокая | Среднее | Mock-контракты; Class C только с разрешением |
| RK-06 | Потеря файлов при переносе | Низкая | Критическое | Источник удаляется только после проверки; журнал; reconcile |
| RK-07 | Ошибки денег/округления | Средняя | Высокое | Decimal-контракт, запрет float, Q8 открыт → отказ вместо угадывания |
| RK-08 | Ожидание «защищённого КП» до доказательств | Средняя | Высокое | NO-GO, отдельный gate (13) |
| RK-09 | Администратор БД обходит журнал | Средняя | Высокое | Явно задокументированная граница доверия; внешняя фиксация (WORM/внешний журнал) — решение ИБ |
| RK-10 | Персональные данные (152-ФЗ) | Средняя | Высокое | OQ-09; минимизация полей; журнал выгрузок |
| RK-11 | Устаревшая справка | Высокая | Среднее | Скриншоты привязаны к версии UI; генерация матрицы ролей |
| RK-12 | Список требований 1–46 не совпадает с ожиданием владельца | Высокая | Среднее | D-11; запросить оригинальный список (OQ-01) |
| RK-13 | Среда разработки без Windows/.NET | Факт | Среднее | Эталон на Python stdlib; spikes S1–S4 перенесены на этап 1 |
