# 04. Матрица прав и таблица действий

## 1. Принципы (обязательны для всех модулей)

1. Решение принимает **сервер в момент эффекта**, в той же транзакции, что и запись (эталон:
   `spikes/reference-core/vector_ref/server.py`, метод `_command` — `BEGIN IMMEDIATE` → auth → authz → эффект → журнал → `COMMIT`).
2. Роль из клиентского запроса **игнорируется**; видимость кнопки — только подсказка (тест `test_client_supplied_role_is_ignored`).
3. Правило = **действие × объект × контекст**: глобальная роль, назначение в проекте, состояние объекта,
   срок полномочия, область (company/department/project), конкретная операция.
4. Нет правила → нет доступа (fail-closed; тест `test_unknown_action_fails_closed`).
5. Каждая выдача роли/назначение — запись с id (= **generation**), сроком и основанием. Отзыв и повторная
   выдача создают *новую* запись; согласования, связанные со старой, не оживают (тест `test_revoke_then_regrant_does_not_revive_approval`).
6. Согласование хранит снимок (hash содержимого + внутреннюю ревизию) и id полномочия; в момент
   финального эффекта проверяется, что снимок тот же и полномочие ещё действует.
7. Admin не получает бизнес-прав автоматически (D-09). Назначение ГИП проекта — **только admin** (зафиксировано).
8. Разделение обязанностей: автор последней правки не согласует сам (A-04; настраиваемо только в сторону ужесточения).
9. Замещение = временная выдача с `valid_until` и основанием; по истечении права исчезают без действий человека (тест `test_expired_grant`).
10. Настройки правил, порогов, провайдера изменяет admin; accountant читает разрешённые ему настройки.
11. Labor-cost (трудозатраты в деньгах, ставки) — **закрыто для всех**, пока правила доступа не подтверждены (OQ-10).
12. Граница доверия: роли защищают от пользователей приложения, **не** от администратора ОС/БД (см. 05, §7).

## 2. Обозначения

`R` читать · `C` создавать · `U` изменять · `A` согласовать/утвердить · `V` отозвать/вернуть ·
`E` экспорт · `M` перенос · `S` восстановить (restore/архив→активно).
Контекст: **G** — глобальная роль; **P** — назначение в этом проекте; **Own** — автор/исполнитель;
**Dept** — руководитель отдела для своих сотрудников; **St** — условие состояния.
Статус строки: ✅ реализовано в эталоне среза 1 · 📐 спроектировано (временное предположение, требует подтверждения).
