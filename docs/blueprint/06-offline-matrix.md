# 06. Матрица офлайн-работы

Классы (машиночитаемо для среза 1 — [`contracts/command-catalog.slice1.json`](../../contracts/command-catalog.slice1.json)):

* **F — `offline_full`**: полностью офлайн; не меняет данных, видимых другим (чтение кэша, локальные заметки, калькуляторы, WIP-копия).
* **Q — `queued`**: локальное изменение с устойчивым `operation_id`; помечено «не синхронизировано»; **не** является подтверждённым действием; сервер заново проверяет права, состояние и версию.
* **O — `online_required`**: финальный эффект требует актуальной проверки сервера; офлайн — отказ с объяснением; в очередь не ставится.

Правило выбора: **O**, если действие (а) меняет деньги, резерв, движение, права, согласование, выдачу, файлы в общем хранилище; (б) имеет внешний эффект (1С, почта); (в) зависит от актуального статуса, который могут изменить другие так, что слияние меняет смысл.

| Область | F (полностью офлайн) | Q (очередь, синхронизация позже) | O (нужен сервер в момент эффекта) | Статус |
|---|---|---|---|---|
| Заказчики | Просмотр, поиск по кэшу | Создать, изменить карточку | Удалить/архивировать (будущее) | ✅ Q реализовано |
| Тендеры | Просмотр | Создать, изменить поля | Смена статуса | ✅ |
| ТКП | Просмотр, черновой расчёт | Создать, изменить черновик | Согласовать, вернуть в черновик, зарегистрировать отправку | ✅ |
| Проект | Просмотр | — | Начать РКД, назначить/отозвать ГИП/РП/участника, смена статуса | ✅ (start/assign) |
| Комплект | Просмотр | Создать, изменить | — | ✅ |
| Задачи | Мои задачи, доска | Создать, комментарий, статус, перенос срока (запрос) | Подтверждение переноса срока постановщиком | 📐 |
| Документы | Открыть кэшированную версию, WIP-копия, «Подготовить рабочий архив ZIP» | «Загрузить без передачи» (файл в локальной очереди, hash), замечание | Согласовать версию, зарегистрировать выдачу/отправку/получение, перенос файлов | 📐 |
| Расчёт комплекта | Diff с последней фиксацией (из кэша) | «Сохранить расчёт» (черновик) | «Зафиксировать комплект» → ревизия проектного итога | 📐 |
| Закупка | Просмотр потребностей, заказов, поставщиков и договоров (снимок «на момент …») | Черновик заказа (✅ D-32), карточка поставщика с реквизитами (✅), договор поставщика (✅ D-33), «Предложить перемещение» (📐) | Отправить на согласование / отозвать / согласовать / вернуть (✅ D-33), разместить / закрыть / отменить заказ, факт поставки (✅ D-32); оформить / отменить замещение, в т. ч. роли в проекте (✅ D-34/D-35) | 🟡 |
| Склад | Просмотр остатков (с отметкой «на момент …») | Черновик прихода/выдачи (без проведения) | Провести движение, резерв, корректировка, подтвердить склад | 📐 |
| Расходники | Просмотр правил | — | Изменение порога/вкл.-выкл. (admin); автосоздание черновика — серверное событие | 📐 |
| Технология | Просмотр ТП, черновые карты | Правка ТП-черновика | Утверждение ТП | 📐 |
| Производство | Мои операции, снимок наряда (загружен при выпуске) | Старт/пауза/завершение операции, таймер, факт, проблема | Выпуск/закрытие наряда, замена в снимке | 📐 (без AI и сети — обязательно) |
| Качество | Просмотр | Черновик ECR, рекламации, замечания | Решение по ECR/ECO, закрытие CAPA | ✅ D-39 (очередь: `claim.register`, `ecr.submit`, `eco.create`/`eco.save`; остальное — онлайн; D-40: классификация, срок и ответ заказчику — онлайн, состояние срока считается и без связи по сохранённым данным) |
| Паспорт | Просмотр | Черновик паспорта | Черновой экспорт (журналируется), передача | 📐 |
| Рабочее время | Смена/пауза/интервалы (локально) | Запись времени, черновик дневного отчёта, отправка на проверку | Принятие/возврат руководителем | 📐 |
| Общение | Чтение кэша | Сообщение в очереди | Отправка e-mail, вложения из защищённых объектов | 📐 |
| Уведомления | Список на момент последнего обновления (кэш) | — | Отметить прочитанными (✅ D-35; не ждёт очереди) | ✅ |

| Вход в систему | Работа под последним пользователем устройства с кэшем | — | Первичный вход, смена пароля | ✅ |

## Поведение на границах (проверено тестами, `tests/test_offline_sync.py`)

| Ситуация | Поведение | Тест |
|---|---|---|
| O-действие офлайн | «Не выполнено и не поставлено в очередь» | `test_queue_offline_and_sync_later` |
| Ответ потерян после отправки | Операция остаётся с тем же `operation_id`; повтор → сохранённый исход, без дубля | `test_lost_response_is_deduplicated`, `test_lost_response_on_online_required` |
| Тот же `operation_id` с другими данными | Отказ `operation_id_reused` | `test_operation_id_reuse_with_other_payload_rejected` |
| Объект изменён другим | Конфликт с текущим состоянием; без слияния; выбор пользователя | `test_conflict_is_not_silently_merged`, `test_conflict_discard_restores_server_state_offline` |
| Конфликт в середине очереди | Остановка; последующие операции ждут | `test_sync_stops_preserving_order` |
| Права отозваны, пока клиент был офлайн | Отказ `no_authority` при синхронизации; черновик можно отменить | `test_rights_revoked_while_offline` |
| Сеанс отозван | Синхронизация останавливается как `unauthenticated`; очередь сохранена | `test_no_token_and_revoked_session` |
| Права на чтение сузились | `pull` очищает кэш от недоступных объектов | `test_pull_respects_read_rights` |

Шифрование локальной БД, привязка устройства, лимит возраста офлайн-черновиков, офлайн-файлы
(загрузка блобов в очереди), граф зависимостей очереди, офлайн-вход с локальной проверкой — спроектированы, кода нет.
