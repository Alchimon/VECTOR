# 53. Экосистема ВЕКТОР: одна программа для всех потребностей компании

> **Статус:** стратегия, принятое направление владельцем (2026-11-25, D-80). Это НЕ план разработки на ближайший
> релиз — это рамка, в которую вписываются следующие годы. Каждая фаза запускается отдельным решением владельца.

## 1. Видение (слова владельца, 2026-11-25)

Экосистема: в будущем у компании будут свои аналоги EPLAN, AutoCAD, Word, Excel, PowerPoint и другие инженерные
и офисные программы, затем смежные — так, чтобы **установка одного нашего приложения закрывала все потребности
компании**. Компания покупает программу: **подписка или постоянная лицензия, с поддержкой и без**, а также
**отдельные модули** (свой EPLAN, свой AutoCAD и т. д.).

## 2. Почему платформа, а не набор программ

Конкурентное отличие — не «ещё один CAD», а **единая среда**, которой у составленных из чужих программ зоопарков
нет и быть не может:

| Что даёт единая платформа | Как это выглядит |
|---|---|
| Один вход, одни права, одна оргструктура | Модуль «Схема» знает проект, комплект и роли без настройки интеграции |
| Данные — объекты БД, а не файлы | Перечень элементов со схемы попадает в расчёт комплекта **сам**, без экспорта/импорта |
| Одна история и аудит | «Кто изменил резистор на схеме» и «кто изменил строку заказа» — один журнал |
| Один офлайн-контур | Конструктор в цеху без сети работает во всех модулях одинаково |
| Один сервер, один бэкап, одна справка | Администратор обслуживает одну установку, а не пять |
| Помодульная продажа | Клиент покупает то, что нужно: «PDM + склад» сегодня, «Схема» — когда созреет |

Вывод для архитектуры: **модуль — это записи в реестре + лицензия, а не отдельный установщик**. Один дистрибутив,
одна схема БД, один цикл обновления; модули включаются лицензией и флагами. Это на порядок снижает матрицу
тестирования и стоимость поддержки по сравнению с «отдельной программой на каждый модуль».

### 3.3. Модули экосистемы (план; порядок — предложение, решение за владельцем)

| Фаза | ID | Название | Аналог | Ключевое отличие-интеграция |
|---|---|---|---|---|
| Ф1 | sheets | ВЕКТОР Таблицы | Excel | движок .xlsx уже есть (`core/xlsx.py`); таблица может быть строкой расчёта/нормы напрямую |
| Ф1 | text | ВЕКТОР Текст | Word | документ — объект с версиями в карточке комплекта, а не файл на диске; шаблоны ЕСКД/СПДС из коробки |
| Ф2 | schema | ВЕКТОР Схема | EPLAN | схемы Э3 по ЕСКД; перечень элементов → спецификация и потребность закупки **автоматически** — главный «убийца» |
| Ф3 | cad | ВЕКТОР CAD | AutoCAD/КОМПАС | 2D ЕСКД сначала; 3D — просмотр/импорт STEP (spike S3), своё ядро — отдельная оценка |
| Ф4 | slides | ВЕКТОР Презентации | PowerPoint | генератор уже есть (`tools/gen_presentation.py`) — формальный вход |
| Ф4 | mail/meet | Почта, календарь, встречи | Outlook/Exchange | после серверной почты; смежно, не инженерно |
| Ф5 | marketplace | Модули и шаблоны партнёров | — | API + подписанные пакеты; только после стабилизации контрактов |

Почему такой порядок: Таблицы и Текст — самая большая ежедневная поверхность и технически проще всего
(нет геометрического ядра); Схема — главный инженерный дифференциатор (связка со спецификацией уже готова в PDM);
механический CAD — самый дорогой (геометрическое ядро, производительность), идёт последним, и сначала — как
просмотр/импорт, а не полноценное моделирование.

## 4. Модель продаж

### 4.1. Лицензии

* **Подписка** — все оплаченные модули + обновления + поддержка на срок. Истекла → льготный период (по умолчанию
  14 дней, всё работает) → **режим «только чтение»**: смотреть, печатать, выгружать можно всегда; изменения —
  после продления. *Данные клиента никогда не становятся заложниками счёта* — это и этика, и защита нас от исков.
* **Бессрочная (постоянная)** — модули работают всегда; **поддержка — отдельной строкой** (обновления и помощь
  до `support_until`; истекла → программа работает, обновления и поддержка — после продления поддержки).
  Это отраслевой стандарт (1С, КОМПАС работают так же).
* **Места:** именные (named) пользователи — честно для on-prem; контроль — по активным сеансам (уже есть
  `sessions`); «без ограничения мест» — вариант для площадки целиком (дороже).
* **Без файла лицензии** — режим демо/стенда: все выпущенные модули доступны (пилоты, обучение, наш стенд).

### 4.2. Ценообразование (рамка, цифры — владельцу)

* Якорь цены комплекта — стоимость замещаемого зоопарка: EPLAN + AutoCAD + MS Office + PDM + 1С-интеграции
  на рабочее место. Комплект должен быть заметно дешевле суммы — иначе аргумента «всё в одном» мало.
* Скидка за комплект модулей (bundle), а не за объём мест — объёмные скидки убивают малый бизнес-сегмент.
* Отдельная политика для учебных заведений (бесплатно/недорого — кадры, привыкшие к ВЕКТОРУ, приходят на заводы)
  и для пилотных клиентов (скидка за обратную связь и референс). — **вопрос владельцу (OQ-53а)**.

### 4.3. Технический механизм лицензии (реализовано в `core/modules.py`, D-80)

Файл JSON с подписью **Ed25519**: проверка локально, интернет не нужен никогда; публичный ключ встроен в
программу, закрытый — только у вендора (не в репозитории); `key_id` позволяет сменить ключ без перевыпуска
старых лицензий. Утилита `tools/make_license.py` — стендовые ключи и выпуск лицензий.

Честно про защиту: исполняемый код у клиента, подпись не остановит злоумышленника с отладчиком — и не должна
мешать честному. Задача механизма: (1) случайное «скопировали папку» не становится неучтёнными местами;
(2) аудит лицензии виден администратору («О программе»: клиент, модули, поддержка до); (3) юридическая защита —
договор. Никаких «телефонит домой», скрытых счётчиков и самоотключений — для on-prem это неприемлемо.

## 5. Форматы и совместимость — мост клиента и наш ров

| Направление | Что делаем | Нюансы |
|---|---|---|
| MS Office | Импорт/экспорт DOCX/XLSX/PPTX (OOXML) с высокой точностью; ODF — импорт | OOXML — открытая спецификация ECMA-376; точность 95% по макетам — реалистичная цель, 100% не бывает ни у кого |
| Чертёж 2D | DXF импорт/экспорт; **DWG — через конвертер** | DWG — закрытый формат Autodesk; варианты: ODA (платное членство, юридически чисто) или честно «только DXF» — **OQ-53б** |
| 3D | STEP AP203/242 (импорт, затем экспорт), STL/IGES | spike S3; JT/Parasolid-ядра — лицензионно дорого, не сейчас |
| EPLAN | Импорт списков (Excel/PDF), DXF листов; родной формат закрыт | Миграция из EPLAN = список элементов + схемы-картинки + пересоздание; честно описать в документации по переезду |
| Свои форматы | **Открытые** XML/JSON со спецификацией | Сознательная открытость: госзаказчики и крупные клиенты требуют гарантию доступа к своим данным; открытый формат — аргумент продажи, а не утечка |

Миграция — главный барьер входа и наш ров после неё: мастера переезда (из Excel-спецификаций, из DXF-библиотек
символов, из 1С-оргструктур), период «двойного ведения» с отчётом расхождений, шаблоны по ЕСКД/СПДС из коробки
(рамки ГОСТ 2.301, шрифты по ГОСТ 2.304 — своя отрисовка, не системные шрифты клиента).

## 6. Юридика и рынок РФ

* **Реестр отечественного ПО** — целевая необходимость: запрет закупок иностранного ПО для госорганов и госкомпаний
  (ПП 1236), льгота по НДС (пп. 26 п. 2 ст. 149 НК), доступ к грантам. Условия: российское правообладательство,
  свои исходники, доля российского труда. Нацелены с первого коммерческого релиза. — **OQ-53в** (юрист/заявка).
* **Товарный знак «ВЕКТОР / VECTOR»** — регистрация до первых продаж (сейчас имя не защищено). — **OQ-53г**.
* **Чистая разработка:** не копировать интерфейсы, код, значки и «look and feel» конкурентов; реализация чужих
  форматов — по открытым спецификациям или через легальные SDK (прецедент Autodesk vs Open Design Alliance —
  чтение DWG допустимо, заимствование кода — нет). Правило уже действует: весь код в репозитории — наш.
* **ФЗ-187 (КИИ), ФСТЭК:** если целимся в КИИ/гос — потребуется сертификация СЗИ/соответствие; это отдельный
  бюджет и сроки, закладывать после первых продаж. — **OQ-53д**.
* **Антимонопольный аспект «всё в одном»:** модули продаются и по отдельности (план и есть), навязывания нет.
* **Эскроу исходников** для крупных клиентов (страх «а если вендор исчезнет») — стандартная практика
  enterprise-продаж; решение — владельцу. — **OQ-53е**.
* **ЕСКД/СПДС/ГОСТ** — не опция, а требование тендеров: библиотеки шаблонов и проверки оформления (штампы,
  листы, изменения) — часть модулей text/schema/cad с первой версии.
