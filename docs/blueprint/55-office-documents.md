# ВЕКТОР · Офисные документы: «Таблицы» и «Текст» (фаза Ф1, D-83)

> Статус: действующая архитектура с 2026-11-25. Решение — D-83 (53-ecosystem.md § 5): свои открытые форматы
> `.vsheetx`/`.vdocx`/`.vslidesx` (ZIP+XML) — надмножество OOXML; чтение и запись OOXML (`.xlsx`/`.docx`)
> без потерь; неизвестные конструкции храним «как есть» и возвращаем при экспорте (round-trip).
> Директива владельца: «аналоги Excel/Word — обязательно: открывать без потерь и их форматы (OOXML), и свои».

## 1. Зачем и где это живёт

Документы в ВЕКТОРЕ — не внешние файлы, а объекты платформы: версии, права, аудит, связи (спецификация ↔
документ проекта, акт ↔ поставка) — тот же подход «документ = база данных», что и для электротехники (53 § 5,
аналог EPLAN). Редакторы «Таблицы» и «Текст» — модули платформы (`office-sheet`, `office-doc`; в плане —
`office-slides`), лицензируются как все (53-ecosystem.md § 4).

| Слой | Что | Где |
|---|---|---|
| Формат | чтение/запись `.vsheetx`/`.vdocx`, импорт/экспорт `.xlsx`/`.docx`, round-trip без потерь | `src/vector/office/` (чистое ядро, без Qt и БД — тестируется изолированно) |
| Модель | книга/лист/ячейка; документ/абзац/прогон | там же |
| Вычисления | формулы таблиц (свой движок, ниже) | `office/formula.py` |
| Сервер | объекты `office_document` (версии, файлы, права, аудит) — общие механики платформы | `server/` (порция Ф1.3) |
| Клиент | редакторы (QML: сетка таблицы, текстовый редактор) | `client/qml/office/` (порция Ф1.4) |

## 2. Свой формат `.vsheetx` (таблицы) — открытый, ZIP+XML

Контейнер ZIP (без шифрования — защита носителя у платформы, не у формата). Имена частей — как в OOXML
(надмножество): кто знает SpreadsheetML, ориентируется сразу.

```
workbook.xml              — книга: листы (имя, id, порядок), именованные диапазоны
sheets/sheet-N.xml        — лист: размеры, ячейки (адрес, тип, значение или формула-строка), стили (id)
styles.xml                — стили ячеек (шрифт/заливка/границы/формат числа), таблица стилей по id
calcchain.xml             — (необязательно) порядок пересчёта; не пишем, читаем терпимо
unknown/                  — неизвестные части из импортированного .xlsx (диаграммы, pivot, vba) — байт-в-байт
```

Ячейка: `<c r="B3" t="n|s|b|str|f" s="12">` + `<v>…</v>` или `<f>СУММ(A1:A9)</f>` (формулы храним в русской
нотации UI + канонической EN для совместимости). Значения: число — Decimal-строкой (деньги точно), строка —
inline или shared, булево, дата — ISO.

Принципы:
1. **Без потерь в обе стороны**: импорт `.xlsx` раскладывает известное по модели; неизвестные части (chart,
   pivotTable, activeX, макросы) складываются в `unknown/` и при экспорте в `.xlsx` возвращаются на место —
   файл открывается в Excel как раньше.
2. **Читаемо человеком**: XML с отступами, адреса ячеек A1-нотация, русские имена функций в `<f>` допустимы
   (при экспорте в .xlsx — переводим в EN).
3. **Детерминированная запись**: канонический порядок частей и ячеек — файлы сравнимы, дифы в Git читаемы.
4. Версия формата в `workbook.xml` (`format_version="1"`) — будущие изменения мигрируются явно.

## 3. Свой формат `.vdocx` (текст) — та же идея (порция Ф1.2)

`document.xml`: абзацы → прогоны (текст + начертание), списки, таблицы, колонтитулы, поля (дата, НомерДокумента —
связь с объектом платформы: шаблон акта подставляет реквизиты). `styles.xml` — именованные стили. Импорт
`.docx` — с сохранением неизвестного (изображения, SmartArt — в `unknown/`).

## 4. Формулы таблиц (движок)

Первая порция: хранение формул как строк + вычислитель базовых: арифметика `+ - * / ^`, скобки, ссылки `A1`,
диапазоны `A1:B9`, функции `СУММ/SUM`, `СРЗНАЧ/AVERAGE`, `МИН/MIN`, `МАКС/MAX`, `СЧЁТ/COUNT`, `ЕСЛИ/IF`,
`ОКРУГЛ/ROUND` (банковское округление не используем — математическое, как в Excel), конкатенация `&`.
Дальше — по потребности пилота. Циклические ссылки — ошибка ячейки `#ЦИКЛ!`, не зависание. Пересчёт —
ленивый топологический (по графу зависимостей), не «вся книга при каждом вводе».

## 5. OOXML: что читаем в первой порции

| Возможность .xlsx | Импорт | Экспорт |
|---|---|---|
| Листы, ячейки (числа/строки/булевы/даты), формулы, merged cells, ширины/высоты, стили базовые (шрифт, заливка, границы, формат числа) | ✅ | ✅ |
| Диаграммы, сводные, макросы, рисунки, условное форматирование | ✅ как «неизвестное» (round-trip) | ✅ возвращаем |
| Повреждённый/не-ZIP файл | честная ошибка «файл не читается» | — |

Тестовый корпус: `tests/office/` — генерация .xlsx самими же (наш экспорт) + фикстуры ручной сборки
(minimal .xlsx по ECMA-376) + round-trip: bytes → модель → bytes (значения и формулы идентичны), и
vsheetx → xlsx → vsheetx (модель идентична).

## 6. Границы фазы Ф1

- **Ф1.1 (сделано, D-90)**: архитектура (этот документ), формат `.vsheetx` (модель, запись/чтение), импорт/экспорт
  `.xlsx` по таблице § 5, вычислитель формул первой порции, round-trip тесты (23 теста). Без сервера и UI.
- **Ф1.2 (сделано, D-91)**: `.vdocx` (модель + OOXML) — абзацы/заголовки/списки/таблицы, начертания,
  round-trip с неизвестным; 9 тестов.
- **Ф1.3**: серверные объекты (версии, права, вложения документов к проектам/поставкам), команды каталога.
- **Ф1.4**: клиентские редакторы (сетка таблицы с вводом/формулами; текстовый редактор), печать/PDF.
- **Ф1.5**: вычислитель формул — расширение, сводные таблицы (свои), диаграммы (свои).

Приёмка Ф1.1: round-trip тесты зелёны на корпусе; `.vsheetx` открывается нашим же читателем; `.xlsx`,
записанный нами, открывается Excel/LibreOffice (проверка LibreOffice headless в стенде, не в CI).

## 7. Дизайн Ф1.3 (сервер) — зафиксирован заранее, реализация следующей порцией

Офисный документ — НОВЫХ таблиц почти не требует: живёт в существующих `documents` + `document_versions`
(неизменяемые версии, дедупликация файлов по SHA-256, квитанции загрузки — уже есть). Отличие от обычного
документа — в том, что платформа понимает его содержимое:

- **Схема v44**: `office_documents` — id, document_id (FK documents), kind (sheet/doc), template_of
  (NULL или id шаблона), title; ничего лишнего — версии и файлы уже умеют всё.
- **Команды каталога v44** (модуль `office`, лицензируется): `office_doc.create` (новый пустой или из шаблона
  с контекстом подстановки — `office.render` внутри), `office_doc.get` (текущая версия → байты .vsheetx/.vdocx),
  `office_doc.save_version` (новая версия из байтов — клиент редактирует локально и сохраняет), 
  `office_doc.render` (шаблон + объект платформы → готовый документ новой версией: контекст собирается
  сервером из проекта/заказчика/организации — только то, что пользователю и так доступно по правам).
- **Права**: `office.manage` (шаблоны), `office.read`/`office.edit` в проекте — как у документов.
- **Аудит**: как у всех команд; версии неизменяемы триггерами (уже).

Клиент (Ф1.4): сетка таблицы (QML TableView + ввод + формулы) и текстовый редактор (QML TextDocument/
собственный рендерер блоков) — офлайн по общему контуру, сохранение новой версией (никакой «правки чужой
версии» — как везде).
