# Полноценный учёт сверхурочных и работы в выходные/праздники

Статус: проектное решение для реализации; не юридическая консультация. Перед вводом в эксплуатацию работодатель утверждает локальный порядок и сверяет его с кадровой службой/юристом и актуальной редакцией законодательства.

## Принятые владельцем рамки

1. Учётный период выбирает компания, длительность — не более года. Допустимые настройки по ответу на уточнение — месяц, квартал или год.
2. Нормативные часы для суммированного учёта берутся по производственному календарю России и подтверждённой недельной норме сотрудника; сменный график не подменяет эту норму.
3. Сбор программной активности — выключен по умолчанию. Допустимы лишь прозрачные события таймера и отчёта с понятным уведомлением сотрудника; скрытый сбор клавиатуры/мыши/программ не реализуется.
4. VECTOR (ВЕКТОР) фиксирует фактические минуты, основания и согласования; денежную оплату рассчитывает 1С.
5. Обычный порядок — предварительное согласование. Для неотложной работы допускается фиксация после выполнения только с причиной и обязательным решением руководителя.
6. Федеральные нерабочие праздничные дни классифицируются отдельно от производственного календаря конкретного графика; классификация не переносит и не сдвигает назначенные смены.
7. Никакого скрытого мониторинга активности: учитываются только явно введённый работником/уполномоченным лицом отчёт о времени и документированное поручение.

## Текущий этап реализации

Реализован серверный начальный поток `overtime.request` / `overtime.decide`: автор указывает период работы, минуты, вид, режим и причину; предварительная заявка допускается только до начала интервала, срочная запись — после окончания. Руководитель по маршруту дневных отчётов принимает отдельное решение, не может решать свою заявку; события создания и решения хранятся отдельно в append-only истории. Pull ограничен автором и теми руководителями, кому видны его дневные отчёты. Денежная ставка и сумма отсутствуют. Это не завершённый табель и не готово для начисления.

Не реализованы: UI (интерфейс), конфигурирование периода компанией и закрытие/корректировка периода, сверка часового лимита/кадровых исключений, подписанное согласие/документ-основание, выгрузка и квитанция 1С. Не разрешать эксплуатацию до реализации этих частей и проверки кадровой службы.

## Предлагаемая модель

- Компания выбирает календарный месяц, квартал или год; система формирует границы по календарю и проверяет длину периода (не более 366 дней).
- Календарная норма периода — сумма нормальных часов пятидневной 40-часовой недели с учётом федеральных праздничных дней и законных переносов для соответствующего года, пересчитанная пропорционально индивидуальной установленной продолжительности рабочего времени (не более нормы по категории работника). Индивидуальный сменный график используется для планирования и выявления отклонения по сменам, но не заменяет нормативную формулу для суммированного учёта. Неполное время, отпуск, болезнь, приём/увольнение и специальные сокращённые нормы уменьшают норму пропорционально подтверждённым кадровым данным; без этих данных расчёт обозначается «неполный», а не угадывается.
- Каждая заявка содержит сотрудника, интервал (начало/окончание), фактические минуты без округления, дату/смену, тип (сверхурочно / выходной / федеральный праздник), основание/задачу, режим (предварительно / неотложно после факта), автора и доказательство согласия работника, если оно требуется. VECTOR не определяет сумму и не хранит ставку.
- До работы руководитель согласует заявку; система сохраняет неизменяемый снимок графика, календаря, нормы и правил классификации. Срочная заявка после факта обязана иметь объяснение, затем руководитель принимает отдельное решение «подтвердить» или «отклонить»; без решения нет подтверждённых часов для выгрузки.
- Отдельные праздничные/выходные минуты не включаются повторно в сверхурочные часы периода, если учтены как работа в выходной/праздник в порядке статьи 153 ТК РФ. Источник нормы/режима и вид компенсации передаются в 1С, где принимается решение о начислении.
- Закрытие периода формирует версионированный табель: план/факт, подтверждённые часы по категориям, решения, причины, применённые редакции нормы/графика/календаря и стабильный идентификатор выгрузки. После закрытия исправление — только корректирующая версия с причиной; прошлый документ и квитанция 1С сохраняются. Повторная выгрузка идемпотентна по идентификатору версии.

## Ретроактивные изменения

Изменение графика/календаря/нормы не переписывает согласованные заявки и закрытые периоды. Для ещё открытого периода изменение создаёт новую редакцию; ранее принятые заявки требуют явного пересмотра руководителем, сравнение старого и нового расчёта показывается в аудите. Федеральный праздник хранится как независимый признак даты и не меняет смену. Неизвестная/оспариваемая классификация блокирует закрытие, но не удаляет исходные часы.

## Неопределённости перед production

Нужно подтвердить с кадровой службой и владельцем: поддерживаемые интервалы настройки; формулу нормы при неполном времени и отсутствиях; перечень оснований и виды согласий; применяемую редакцию ТК и ограничения по категориям сотрудников; формат обмена и подтверждение импорта 1С. Учётный период в смысле суммированного учёта по статье 104 ТК РФ нельзя автоматически приравнивать к произвольному периоду без кадрового основания.

## Правовой ориентир

Официальная публикация Федерального закона от 25.05.2026 № 144-ФЗ: https://publication.pravo.gov.ru/document/0001202605250023 (поправки к ТК РФ; учитывать дату вступления отдельных норм в силу). Статьи 91, 99, 104, 113, 152 и 153 ТК РФ требуют юридической сверки для внедряемой редакции. В частности, исключение праздничных/выходных часов из повторного расчёта сверхурочных связано с условиями статьи 152, а не должно применяться без проверки способа компенсации.
