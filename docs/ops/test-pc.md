# Тестовый стенд ВЕКТОР на ПК

Инструкция для тестировщика: как за 10–15 минут поднять на своём компьютере **сервер и клиент ВЕКТОР**
с вымышленными демо-данными и что проверить.

> ⚠️ **Только для теста.** База — SQLite, сертификат — тестовый (действует 30 дней), данные — вымышленные.
> Для работы в компании используйте [install.md](install.md): PostgreSQL / MS SQL, сертификат CA компании,
> резервные копии по [backup-restore.md](backup-restore.md).
>
> Статусы: ✅ — пройдено в песочнице разработки (Linux); 🟡 — подготовлено, но на настоящей Windows
> ещё не запускалось: **ваш первый запуск и есть эта проверка** (Class C). Если что-то пошло не так — см. § 9.

## 1. Что получится

```
%USERPROFILE%\VECTOR-test\          ← каталог стенда (можно выбрать другой)
├─ venv\                            программа (отдельное окружение Python, систему не меняет)
├─ certs\ca.pem, server.pem, server.key   тестовый сертификат (ключ доступен только вам)
├─ data\vector.sqlite               база стенда
├─ backups\                         зашифрованные резервные копии
├─ server.toml, db.url, backup.key  конфигурация, строка подключения, ключ копий
├─ start-server.cmd                 запуск сервера     (ярлык «ВЕКТОР — сервер (тест)»)
├─ start-client.cmd                 запуск клиента     (ярлык «ВЕКТОР — клиент (тест)»)
├─ backup.cmd                       резервная копия
└─ demo-accounts.txt                список демо-учёток (без паролей)
```

Сервер и клиент работают на одном ПК; по желанию — клиенты на других ПК сети (§ 7).

## 2. Что нужно

| | |
|---|---|
| ОС | Windows 10 или 11, 64-бит 🟡 · Linux с графическим рабочим столом ✅ (§ 10) |
| Python | **3.12 или 3.13, 64-бит** с [python.org](https://www.python.org/downloads/windows/) (подходит 3.11–3.14). При установке отметьте **«Add python.exe to PATH»** |
| Интернет | при установке: загрузка библиотек с pypi.org (~150 МБ) |
| Диск | ~1 ГБ |
| Права | **администратор не нужен** (кроме открытия порта для сети, § 7) |

Python из Microsoft Store не рекомендуется (ограничения доступа к папкам); установщик с python.org — надёжнее.

## 3. Скачать

1. Скачайте архив с исходным кодом:
   [VECTOR — ветка разработки (ZIP)](https://github.com/Alchimon/VECTOR/archive/refs/heads/arena/c599ae91-vector.zip)
   (после слияния в основную ветку — [main (ZIP)](https://github.com/Alchimon/VECTOR/archive/refs/heads/main.zip)).
2. **До распаковки**: правый щелчок по ZIP → «Свойства» → отметьте **«Разблокировать»** → «ОК».
   Иначе Windows будет переспрашивать при запуске каждого файла из интернета.
3. Распакуйте в **короткий путь**, например `C:\VECTOR-src` (длинные пути Windows не любит).
   Внутри должна быть папка с `README.md`, `src`, `deploy`.

## 4. Установка на одном ПК 🟡

1. Откройте `deploy\test-stand\windows\` и дважды щёлкните **`setup.cmd`**.
   - Если появится «Windows защитила ваш компьютер» — «Подробнее» → «Выполнить в любом случае»
     (скрипт не подписан; это тестовая сборка).
2. Скрипт сам: найдёт Python → создаст `%USERPROFILE%\VECTOR-test` → установит программу (несколько минут)
   → выпустит тестовый сертификат → создаст базу.
3. Он спросит два пароля (ввод не отображается — это нормально):
   - **пароль администратора** `admin` — не короче 12 символов;
   - **пароль демо-учёток** — один на всех демо-пользователей, тоже от 12 символов. Запишите оба.

   Простые пароли (`123456789012`, `password1234` и т. п.) и пароль, содержащий логин, сервер не примет: появится
   сообщение с причиной, **ничего не будет создано**, и установщик спросит пароль снова (до трёх попыток).
4. В конце появится «Готово» и два ярлыка на рабочем столе. Окно можно закрыть.

Параметры (запуск из командной строки в той же папке): `setup.cmd -Dir D:\VECTOR-test` — другой каталог;
`-NoDemo` — без демо-данных; `-Port 9443` — другой порт; `-NoShortcuts` — без ярлыков; `-Lan` — см. § 7.

### Самопроверка стенда (1 минута)

Перед ручной проверкой убедитесь, что стенд готов: при **запущенном сервере** дважды щёлкните
`deploy\test-stand\windows\check-stand.cmd` в распакованной папке (стенд в другом каталоге —
`check-stand.cmd D:\VECTOR-test`; Linux — `bash deploy/test-stand/linux/check-stand.sh --dir ~/vector-test`).
Она спросит пароль демо-учёток и проверит по HTTPS, тем же способом, что и клиент:

* сертификат стенда принят и сколько дней он ещё действует; без сертификата соединение отклоняется;
* все демо-учётки входят и получают свои роли;
* демо-данные для сценариев на месте: заказ № 5 на согласовании, уведомления руководителю отдела и согласующему,
  `m.lebedev` замещает ГИП в П-2026-014, у `a.smirnova` — два проекта (D-35, П-11).

Итог «**стенд готов к проверке**» — можно начинать. «Предупреждение» — стенд работает, но часть сценариев на этих
данных не проверить (например, заказ № 5 уже согласовали или стенд обновлён со старой версии) — там же сказано, что
делать. «Ошибка» — с подсказкой (сервер не запущен, не тот пароль, не тот сертификат).
Самопроверка **ничего не меняет** (не согласует, не отмечает прочитанным); после 5 неверных паролей подряд демо-учётка
блокируется на 15 минут — как при обычном входе.

## 7. Тест в сети (сервер на одном ПК, клиенты на других) 🟡

На **ПК сервера** установите стенд с параметром `-Lan` (из командной строки в папке
`deploy\test-stand\windows`):

```bat
setup.cmd -Lan
```

Сертификат будет выпущен на имя ПК и его IP-адреса, сервер будет слушать сеть. Входящий порт 8443
откроется автоматически, если запустить `setup.cmd` от администратора; иначе скрипт покажет команду.

На **каждом ПК клиента** (там тоже нужен Python, § 2, и распакованный архив, § 3):

1. Скопируйте с ПК сервера файл `VECTOR-test\certs\ca.pem` (флешка, общая папка).
2. В папке `deploy\test-stand\windows`:

```bat
setup.cmd -ClientOnly -Server https://ИМЯ-ПК-СЕРВЕРА:8443 -CaFile C:\путь\к\ca.pem
```

Ставится только клиент; ярлык «ВЕКТОР — клиент (тест)». Если подключение не проходит: проверьте, что сервер
запущен, порт открыт (`Test-NetConnection ИМЯ-ПК -Port 8443` в PowerShell) и имя в адресе — то же, что
выводил `setup.cmd -Lan`. Сообщение о сертификате — значит, взят не тот `ca.pem`: клиент намеренно не
соединяется с сервером, которому не доверяет.

## 7а. Обновление стенда до новой версии (данные сохраняются)

Если стенд уже установлен (например, ранней версией), а вы скачали новую:

1. Остановите сервер (Ctrl+C в окне сервера) и закройте клиент.
2. Скачайте и распакуйте новую версию (§3) **в новую папку**, например `C:\VECTOR-src2`.
3. Запустите `deploy\test-stand\windows\update.cmd` **из новой папки** (стенд в другом каталоге —
   `update.cmd D:\VECTOR-test`). Скрипт: установит новую версию в окружение стенда → сделает зашифрованную
   копию базы с проверкой (`backups\vector-premigrate-…`) → обновит схему базы (всё или ничего) → проверит.
4. Запустите сервер ярлыком, как обычно.

Linux: `bash deploy/test-stand/linux/update-test-stand.sh [--dir ~/vector-test]`.
Если обновление прервалось с ошибкой — база не изменена; пришлите текст ошибки (§9).

> **Для проверки нового шага ставьте свежий стенд.** Обновление сохраняет ваши данные, но **новые демо-данные не
> добавляет**, а уведомления (D-35) появляются только о событиях после обновления. Поэтому для чек-листа
> (например, П-11) удобнее стенд с нуля в новый каталог — старый не трогается:
>
> ```bat
> setup.cmd -Dir %USERPROFILE%\VECTOR-test2
> ```
>
> Ярлыки «ВЕКТОР — сервер / клиент (тест)» переключатся на новый стенд. Перед запуском закройте сервер старого
> стенда (порт тот же). Старый удаляется по § 8. Готов ли стенд — покажет самопроверка (§ 5).
Новые демо-данные (например, расчёты комплектов, склад, учётки `i.belova` / `s.morozov` / `v.zaitseva`, кабель для
ручного сопоставления, поставщики, реквизиты, договоры и заказы, технологи и производство, ТП и наряд № 1) в уже существующую базу
**не добавляются** — их можно создать самостоятельно (`admin` → новый пользователь → роль «Склад», «Закупка»,
«Согласование закупок», «Технолог» или «Производство»)
или поставить стенд заново в пустой каталог.

## 8. Удаление стенда

1. Закройте окна сервера и клиента.
2. Удалите каталог `%USERPROFILE%\VECTOR-test` и ярлыки «ВЕКТОР — … (тест)» с рабочего стола.
3. Локальные данные клиента: `%LOCALAPPDATA%\VECTOR`; настройки: реестр `HKCU\Software\VECTOR`;
   секрет устройства: «Диспетчер учётных данных» → «Учётные данные Windows» → записи `VECTOR-desktop`.
4. Если открывали порт: `Remove-NetFirewallRule -DisplayName "VECTOR test server 8443"` (от администратора).
5. Python удаляется отдельно, если больше не нужен.

## 9. Если что-то не так — как сообщить

Создайте задачу на GitHub: [Issues → New issue](https://github.com/Alchimon/VECTOR/issues/new) и укажите:

- что делали (шаги), что ожидали, что получилось; учётку (логин), если важно;
- снимок экрана;
- текст из окна сервера и/или консоли клиента (выделите мышью и нажмите `Enter` — текст скопируется) — **без паролей**;
- версию Windows, масштаб экрана, версию Python (`py --version`).

Частые ситуации:

| Сообщение | Что делать |
|---|---|
| «Не найден Python 3.11–3.14 (64-бит)» | Установите Python 3.12/3.13 с python.org с отметкой «Add python.exe to PATH», запустите `setup.cmd` снова |
| «Каталог … не пуст» | Удалите старый стенд (§ 8) или `setup.cmd -Dir <другой каталог>` |
| «Не удалось установить программу» | Нет доступа к pypi.org (прокси/межсетевой экран компании) — обратитесь к администратору сети |
| В клиенте «Сертификат сервера не прошёл проверку» | Не тот `ca.pem` или сертификат истёк (30 дней) — пересоздайте стенд |
| В клиенте «нет связи» | Окно сервера закрыто или упало — запустите ярлык сервера и посмотрите журнал |
| Сервер: «address already in use» | Порт занят (возможно, сервер уже запущен) — закройте второе окно или `-Port 9443` при установке |
