# Релизный контур ВЕКТОР (этап 8; D-80)

> Статус: действующий порядок с 2026-11-25. Пилот и приёмка — по [pilot.md](pilot.md); пакет для стенда —
> по [test-pc.md](test-pc.md). Эта инструкция — про версии, критерии и каналы выпуска.

## 1. Схема версий

`МАЖОР.МИНОР.ПАТЧ` + суффиксы разработки:

| Версия | Смысл |
|---|---|
| `0.MINOR.0.dev0` | текущая разработка после завершённого MINOR-цикла (сейчас `0.3.0.dev0`: этапы 2–7 закрыты, D-56…D-80) |
| `0.9.0-rc.N` | кандидат в пилот: заморозка функций, только исправления из пилотного чек-листа |
| `1.0.0` | приёмка пилота владельцем (протокол § 4 pilot.md) |
| `1.MINOR.0` | новые функции после 1.0 (порции D-NN); `PATCH` — только исправления |

Правила: версия в `pyproject.toml` и `src/vector/__init__.py` совпадают (проверяется тестом); каждая версия —
метка Git `v1.2.3`; CHANGELOG — запись на каждую версию; схема БД и каталог контрактов растут только вперёд
(миграции идемпотентны, старые версии объектов не переписываются).

## 2. Совместимость клиент ↔ сервер (политика N-2)

Каталог команд версионируется (сейчас v43, 178 команд). Сервер версии N принимает клиентов N, N−1 и N−2;
клиент старше допустимого получает понятный отказ «обновите программу» с версией сервера. Обновление стенда —
`vector-server migrate` с проверенной копией до изменений (D-22), затем обновление клиентов; откат — восстановление
копии ([backup-restore.md](backup-restore.md), [restore-drill.md](restore-drill.md)).

## 3. Критерии выпуска (gates) любой версии

1. Полный прогон зелёный: Class A (ядро + сервер на SQLite и встроенном PostgreSQL, клиент, UI offscreen) —
   актуальный счётчик в README; эталон спайка — 36/36; стражи синхронизации (справка, контракты, подсказки,
   ссылки в документации) чисты.
2. `pip-audit` по продуктовым зависимостям — чисто (практика в SECURITY.md).
3. CHANGELOG, decision-log (D-NN/A-NN), трассировка, руководства обновлены в той же порции.
4. Скриншоты новых разделов — в `docs/screenshots` (обе темы).
5. Неразрешённых критических ❌ пилотного чек-листа нет; открытые вопросы владельцу перечислены в релиз-заметках.

Для `1.0.0` дополнительно: протокол пилота заполнен владельцем, Windows-стенд пройден (#10), MS SQL проверен (#3)
или зафиксирован как «поддерживается с версии X.Y».

## 4. Каналы поставки

| Канал | Для кого | Состав |
|---|---|---|
| Тестовый стенд | владелец, пилоты | ZIP по test-pc.md (сервер + клиент + демо-данные + обновление с сохранением данных) |
| Релиз GitHub | разработка | метка `v*`, релиз-заметки из CHANGELOG, артефакт-сборка стенда |
| Поставка клиенту | коммерция (после 1.0) | установщик Windows (#4 — Class C), файл лицензии (`tools/make_license.py`, D-80), руководства, учебное восстановление |

## 6. Чек-лист «выпускаем версию»

- [ ] версия поднята в `pyproject.toml` и `src/vector/__init__.py`, тест совпадения зелёный;
- [ ] § 3 gates выполнены; счётчики README/оглавления обновлены;
- [ ] `git tag vX.Y.Z` + релиз-заметки (CHANGELOG → GitHub release);
- [ ] пакет стенда пересобран и пройден «чистая установка → обновление → восстановление из копии»;
- [ ] владельцу отправлены: ссылка на релиз, релиз-заметки, список открытых вопросов.
